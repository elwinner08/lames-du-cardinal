## 2. Findings PROBABLES

Éléments vraisemblablement inutiles mais qui pourraient valoir un test rapide en jeu.

### 2.1 Mismatch extensions — `LAMES.signes` dans `config.mjs`

**Fichier :** `module/helpers/config.mjs:65-68`

```js
LAMES.signes = {
  griffe:  { …, icon: "systems/…/assets/signes/griffe.svg" },   // fichier .png présent
  souffle: { …, icon: "systems/…/assets/signes/souffle.svg" },  // fichier .png présent
  sang:    { …, icon: "systems/…/assets/signes/sang.svg" },     // fichier .png présent
  ecaille: { …, icon: "systems/…/assets/signes/ecaille.svg" }   // fichier .png présent
};
```

Les fichiers réels sont `.png` mais référencés en `.svg`. Comme l'utilisateur a confirmé que `assets/signes/` n'est pas utilisé aujourd'hui (réservé à un futur feature), l'impact est nul pour l'instant. Le champ `icon` ne semble lu nulle part (grep sur `LAMES.signes` → seulement des accès `.label` / `.couleur`, jamais `.icon`).

**Action (double option) :**
- Corriger les extensions `.svg` → `.png` *(futur-proofing si la feature arrive)*
- OU supprimer les champs `icon: …` entièrement *(jamais lus → morts)*

Recommandé : **supprimer les 4 entrées `icon`** (mode A). La feature future les recréera si besoin.

### 2.2 Variable CSS fantôme — `--lames-warning`

**Fichier :** `styles/lames.css:3135`

```css
.lame-epee-status.evanoui { color: var(--lames-warning); }
```

`--lames-warning` **n'est pas défini** dans le bloc `:root` (`styles/lames.css:11-41`). Le style tombera sur `color: unset` → couleur par défaut du navigateur (héritée, probablement `--lames-text`).

**Deux options :**
1. Définir `--lames-warning: #b8860b;` (dark goldenrod) dans `:root` pour rendre les PJ évanouis visuellement distincts.
2. Remplacer par `var(--lames-gold-dark)` ou une valeur inline.

Recommandé : **option 1** (ajouter `--lames-warning: #b8860b;`) — cohérent avec le reste de la palette et donne un vrai feedback visuel aux joueurs évanouis.

## 5. Opportunités mode C (refactoring ultérieur)

Non traité dans cet audit passif, mais à considérer quand tu passeras en mode C :

### 5.1 Pattern `get title()` dupliqué dans 8 sheets

Toutes les sheets (`LameSheet, FigurantSheet, ArcaneSheet, ArmeSheet, EcoleSheet, EpeeSheet, ProfilSheet, GenericItemSheet`) définissent :

```js
get title() { return this.document.name; }
```

→ **Factorisable** en créant une classe de base (ex : `LamesActorSheet`, `LamesItemSheet`) ou un mixin.

### 5.2 Pattern `_prepareContext` ItemSheet dupliqué

4 sheets (`ArmeSheet, EcoleSheet, EpeeSheet, GenericItemSheet, ProfilSheet, ArcaneSheet`) partagent :

```js
context.system = this.item.system;
context.item = this.item;
context.isFromCompendium = !!(this.item.pack || this.item._stats?.compendiumSource);
context.descriptionEnriched = await foundry.applications.ux.TextEditor.implementation.enrichHTML(…);
```

→ **Factorisable** dans une méthode `super._prepareCommonItemContext()`.

### 5.3 `foundry.applications.ux.TextEditor.implementation.enrichHTML` répété ~20 fois

Un petit helper `enrichItem(item, fields)` réduirait la verbosité et centraliserait le pattern.

### 5.4 Duplication entre `LameSheet.#onTestEscrime`, `#onTestOccultisme`, `#onCompetenceRoll`

Ces 3 handlers construisent chacun un dialogue similaire (select difficulté + select type de test) avec 80% de code commun. Factorisable en `async _promptTestParams(options)`.

### 5.5 Pattern `configureListener avatar click` dupliqué entre LameSheet et FigurantSheet

`LameSheet._onRender` et `FigurantSheet._onRender` ont le même bloc :

```js
const avatar = this.element.querySelector(".profile-img");
if (avatar) avatar.addEventListener("click", …);
```

→ **Factorisable** dans la classe de base commune.

### 5.6 Texts hardcodés français dans dialogues

Plusieurs strings français hardcodés dans les handlers (`ui.notifications.warn("Plus de Ténacité disponible !")`, titres de dialogues, etc.) → devraient passer par `game.i18n.localize(…)`.
